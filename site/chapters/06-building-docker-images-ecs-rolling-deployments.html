Docker ও Amazon ECS — পরিচিতি

Docker কী?

Docker হলো একটি containerization tool যা application-কে standardized unit — container-এ package করে। Container-এ application code, dependencies, system libraries এবং runtime সব থাকে। ফলে server configure না করেই যেকোনো Docker Engine-এ চালানো যায়।

flowchart TD SRC["Source Code\n+ Dockerfile"] -->|docker build| IMG["Docker Image"] IMG -->|docker push| ECR["Amazon ECR\n(Private Registry)"] ECR -->|ECS pulls image| TASK["ECS Task\n(Running Container)"] TASK --> ALB["Application Load Balancer"] ALB --> USER["Users"]

Docker build → ECR push → ECS deployment flow।

Amazon ECS Concepts

Task Definition
Container-এর specification JSON file। Docker image, CPU/memory, ports, environment variables define করে। Immutable — update করলে নতুন revision তৈরি হয়।
Task
Task definition-এর running instance। Container(s) চলার environment।
ECS Service
নির্দিষ্ট সংখ্যক task সবসময় running রাখার mechanism। ALB attach করা যায়। Rolling deployment-এর primary unit।
ECS Cluster
Tasks ও services-এর logical group। Regional resource।
Fargate Capacity Provider
Serverless infrastructure — AWS manage করে, EC2 instance manage করতে হয় না।
Auto Scaling Group Capacity Provider
EC2 container instances-এর ASG — ECS managed scaling সহ।

ECS Deployment Types

  • ECS Standard (Rolling): CodePipeline-এর direct integration। imagedefinitions.json দিয়ে নতুন task definition revision তৈরি করে rolling update করে।
  • ECS Blue/Green (CodeDeploy): ALB traffic shifting সহ। এই section-এ cover হয়নি।

Docker Build-এর জন্য CodeBuild Buildspec

Dockerfile (Multi-stage)

# Build stage — Angular app build করে
FROM node:20 AS builder
WORKDIR /my-project
COPY . .
RUN npm install && ng build -c production

# Final stage — শুধু static files + Nginx
FROM nginx:1.25
EXPOSE 80
COPY --from=builder /my-project/dist/my-angular-project /usr/share/nginx/html

Multi-stage Dockerfile-এর সুবিধা: final image-এ শুধু deployable files থাকে — node_modules, Angular CLI, source code বাদ।

buildspec.yml (Docker Hub push)

version: 0.2

phases:
  pre_build:
    commands:
      # Docker Hub login (pull limit এড়াতে)
      - echo ${DOCKERHUB_TOKEN} | docker login -u ${DOCKERHUB_USER} --password-stdin

  build:
    commands:
      - docker build -t my-angular-app:latest .

  post_build:
    commands:
      - docker tag my-angular-app:latest ${DOCKERHUB_USER}/my-angular-app:latest
      - docker push ${DOCKERHUB_USER}/my-angular-app:latest
Docker Hub pull limit: unauthenticated user-রা CodeBuild-এর অন্যান্য execution-এর সাথে limit share করে। Login করলে নিজের limit পাওয়া যায়।

CodeBuild Project-এর বিশেষ Settings (Docker Build)

  • Privileged mode: ✅ Enable করতে হবে — Docker daemon access-এর জন্য। CodeBuild container-এর ভেতরে Docker চালাতে privileged mode দরকার।
  • Architecture: x86_64 (Intel-based) বা aarch64 (ARM) — deploy target-এর architecture-এর সাথে match করতে হবে।
  • Environment variables: DOCKERHUB_USER, DOCKERHUB_TOKEN — pipeline action বা CodeBuild project-এ define করুন।

Docker Image Build করার Pipeline

  1. Source: GitHub repository (Dockerfile ও buildspec.yml সহ)।
  2. Build: CodeBuild project → Privileged mode enable।
  3. Deploy: (পরে যোগ হবে) — প্রথমে শুধু build stage।

Environment variables pipeline build action-এ define করা যায় — এটি CodeBuild project configuration-এর চেয়ে higher precedence।

Environment Variable Precedence (Lowest → Highest)

  1. buildspec file
  2. CodeBuild project configuration
  3. CodePipeline action configuration

Secrets Manager Environment Variables

Plaintext environment variables পাইপলাইনে visible থাকে। AWS Secrets Manager-এ credentials encrypted রাখা যায়।

Secret তৈরি

  1. AWS Secrets Manager → Store a new secret।
  2. Secret type: Other type of secret।
  3. Key/value: token = Docker Hub token, user = Docker Hub username।
  4. Secret name: dockerhub

CodeBuild-এ Permission যোগ করা

CodeBuild project-এর IAM role-এ inline policy:

{
  "Effect": "Allow",
  "Action": "secretsmanager:GetSecretValue",
  "Resource": "arn:aws:secretsmanager:REGION:ACCOUNT:secret:dockerhub-*"
}

buildspec-এ Reference করা

env:
  secrets-manager:
    DOCKERHUB_TOKEN: dockerhub:token
    DOCKERHUB_USER: dockerhub:user
Secrets Manager প্রতিটি secret-এর জন্য charge করে। প্রয়োজনে free alternative হিসেবে Parameter Store ব্যবহার করুন।

Parameter Store Environment Variables

AWS Systems Manager Parameter Store হলো Secrets Manager-এর একটি free alternative। Standard tier-এ encrypted parameter store করা যায়।

Parameter তৈরি

  1. SSM Console → Parameter Store → Create parameter।
  2. Name: /dockerhub/token (path hierarchy ব্যবহার করুন)।
  3. Tier: Standard (free, 4KB পর্যন্ত)।
  4. Type: SecureString — KMS দিয়ে encrypted।
  5. দ্বিতীয় parameter: /dockerhub/user

CodeBuild IAM Permission

{
  "Effect": "Allow",
  "Action": "ssm:GetParameters",
  "Resource": "arn:aws:ssm:REGION:ACCOUNT:parameter/dockerhub/*"
}

Path-based parameter name ব্যবহার করলে wildcard দিয়ে সব parameter-এ একটি rule কাজ করে।

buildspec-এ Reference করা

env:
  parameter-store:
    DOCKERHUB_TOKEN: /dockerhub/token
    DOCKERHUB_USER: /dockerhub/user

Docker Image Amazon ECR-এ Push করা

ECR Repository তৈরি

  1. Amazon ECR Console → Create repository।
  2. Type: Private।
  3. Name: my-angular-app
  4. Tag immutability: Disable (same tag দিয়ে push করার জন্য)।

CodeBuild IAM Permission (ECR)

CodeBuild project-এর IAM role-এ codebuild-ecr-policy.json-এর permissions add করুন। ECR login ও push-এর জন্য প্রয়োজনীয় permissions:

buildspec.yml (ECR push)

version: 0.2

env:
  variables:
    ECR_REPO_NAME: my-angular-app
  parameter-store:
    DOCKERHUB_TOKEN: /dockerhub/token
    DOCKERHUB_USER: /dockerhub/user

phases:
  pre_build:
    commands:
      # Docker Hub login (pull limit এড়াতে)
      - echo ${DOCKERHUB_TOKEN} | docker login -u ${DOCKERHUB_USER} --password-stdin
      
      # ECR login
      - ECR_MAIN_URI=${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com
      - aws ecr get-login-password --region ${AWS_REGION} | docker login --username AWS --password-stdin ${ECR_MAIN_URI}
      
      # ECR image URI (commit ID tag)
      - ECR_IMAGE_URI=${ECR_MAIN_URI}/${ECR_REPO_NAME}:${CODEBUILD_RESOLVED_SOURCE_VERSION:0:8}

  build:
    commands:
      - docker build -t my-angular-app:latest .

  post_build:
    commands:
      - docker tag my-angular-app:latest ${ECR_IMAGE_URI}
      - docker push ${ECR_IMAGE_URI}
      
      # ECS deploy action-এর জন্য imagedefinitions.json তৈরি
      - printf '[{"name":"angular-app","imageUri":"%s"}]' ${ECR_IMAGE_URI} > imagedefinitions.json

artifacts:
  files:
    - imagedefinitions.json

ECS Task Definition তৈরি করা

  1. ECS Console → Task definitions → Create new task definition।
  2. Task definition family name: my-angular-task-definition
  3. Container name: angular-app
  4. Image URI: ECR repository-এর latest image URI কপি করুন।
  5. Port: 80 (Nginx)।
  6. App environment: AWS Fargate ও Amazon EC2 উভয়ই।
  7. OS/Architecture: Linux/X86_64 (Intel-based build environment-এর সাথে match)।
  8. Task size: CPU = 0.25 vCPU, Memory = 0.5 GB (smallest)।
Architecture মেলানো জরুরি। Intel-based CodeBuild-এ build করা image ARM-based Fargate-এ চলবে না এবং vice versa।
Task definition update করা যায় না — নতুন revision তৈরি হয়। ECS deploy action প্রতিটি deployment-এ নতুন revision তৈরি করে।

ECS Cluster তৈরি করা

  1. ECS Console → Clusters → Create cluster।
  2. Cluster name: my-cluster
  3. Networking: default VPC।
  4. Infrastructure: AWS Fargate (default, always added) + Amazon EC2 instances (ASG capacity provider-এর জন্য যোগ করুন)।

ASG Capacity Provider Configuration

  • OS: Amazon Linux 2 (Intel-based)।
  • EC2 instance type: t3.micro।
  • Min capacity: 0, Max: 5।

Min = 0 মানে কোনো task না থাকলে instance নেই — cost বাঁচায়। ECS নিজেই ASG scale করবে।

Fargate-এ ECS Service তৈরি করা

  1. ECS Cluster → Services tab → Deploy।
  2. Capacity provider: FARGATE।
  3. Application type: Service।
  4. Task definition: আগে তৈরি করা, latest revision।
  5. Service name: my-rolling-service
  6. Desired tasks: 2
  7. Deployment type: Rolling update।
  8. Min running tasks: 100%, Max: 200%।
  9. Deployment circuit breaker: প্রথমে Disable করুন (failure scenario দেখার জন্য)।
  10. Networking: default VPC, all subnets, Public IP enable।
  11. Load balancer: Application Load Balancer → Create new → my-rolling-service-alb।
  12. Target group: my-rolling-service-target-group, HTTP, health check path /।
  13. Health check grace period: 0।
Deregistration delay কমান: Default 300s (5 min) deployment slow করে। Target group-এর Attributes-এ 30s-এ নামিয়ে রাখুন।
Load balancer তৈরির পরে ALB-এ একটি নতুন security group attach করতে হবে যা HTTP port 80 allow করে। Default security group শুধুমাত্র VPC-internal communication-এর জন্য।

Pipeline-এ ECS Standard Deploy Action

imagedefinitions.json কী?

ECS Standard deploy action-এর জন্য CodeBuild-কে একটি JSON file তৈরি করতে হয় যা বলে কোন container-কে কোন new image দিয়ে update করতে হবে।

[
  {
    "name": "angular-app",
    "imageUri": "123456789.dkr.ecr.eu-west-1.amazonaws.com/my-angular-app:abc12345"
  }
]

name = task definition-এর container name। imageUri = নতুন Docker image-এর URI।

Deploy Action Configure করা

  1. Pipeline → Edit → Build stage-এর পরে Add stage → name: Deploy।
  2. Add action group → name: DeployToECS।
  3. Action provider: Amazon ECS (Blue/Green নয়)।
  4. Input artifact: BuildArtifact।
  5. Cluster name: my-cluster।
  6. Service name: my-rolling-service।
  7. Image definitions file: imagedefinitions.json (default)।

Rolling Deployment Flow

sequenceDiagram participant CP as CodePipeline participant CB as CodeBuild participant ECR as Amazon ECR participant ECS as Amazon ECS CP->>CB: Trigger build CB->>ECR: docker push new-image:commit-id CB->>CP: Output: imagedefinitions.json (BuildArtifact) CP->>ECS: Deploy action (imagedefinitions.json) ECS->>ECS: Create new task definition revision ECS->>ECS: Launch 2 new tasks (new image) ECS->>ECS: Register new tasks to ALB target group ECS->>ECS: Deregister old tasks from ALB ECS->>ECS: Stop old tasks ECS-->>CP: Deployment complete

ECS Standard rolling deployment flow: CodeBuild → ECR push → ECS rolling update।

Commit ID দিয়ে Docker Image Tagging

সমস্যা: latest tag দিয়ে push করলে পুরনো image untagged হয়ে যায়। Rollback-এ নতুন task-গুলো failed image pull করে।

সমাধান: CODEBUILD_RESOLVED_SOURCE_VERSION

CodePipeline এই environment variable-এ Git commit ID (40 chars) pass করে।

# buildspec-এ ECR_IMAGE_URI-তে latest-এর বদলে:
ECR_IMAGE_URI=${ECR_MAIN_URI}/${ECR_REPO_NAME}:${CODEBUILD_RESOLVED_SOURCE_VERSION:0:8}

:0:8 syntax bash substring — index 0 থেকে 8 characters।

সুবিধা

  • প্রতিটি image unique tag — পুরনো image accessible থাকে।
  • Task definition revision-এ image URI-তে commit ID দেখা যায়।
  • Rollback হলেও পুরনো task-গুলো correct image চালায়।
  • Image tag দিয়ে CodeCommit-এ সেই commit খুঁজে পাওয়া যায়।

ECR Public Gallery ব্যবহার করা

Docker Hub-এ Docker pull limit আছে। ECR Public Gallery-তে Docker official images থাকে — AWS network-এর ভেতরে।

Dockerfile-এ base image পরিবর্তন

# আগে (Docker Hub):
FROM node:20 AS builder
FROM nginx:1.25

# পরে (ECR Public Gallery):
FROM public.ecr.aws/docker/library/node:20 AS builder
FROM public.ecr.aws/docker/library/nginx:1.25

Pattern: public.ecr.aws/docker/library/IMAGE_NAME:TAG

pre_build:
  commands:
    # ECR Public Gallery login (us-east-1 required)
    - aws ecr-public get-login-password --region us-east-1 | docker login --username AWS --password-stdin public.ecr.aws
ECR Public Gallery login-এ region অবশ্যই us-east-1 দিতে হবে — অন্য region কাজ করবে না।

CodeBuild IAM Permission

CodeBuild role-এ AmazonElasticContainerRegistryPublicReadOnly managed policy attach করুন।

Docker Hub login তখনও রাখার দরকার নেই কারণ base images ECR থেকে আসছে। Docker Hub login command এবং credentials পুরোটা সরিয়ে ফেলা যায়।

ECS Rolling Deployment Failure

Deployment circuit breaker disable থাকলে ব্যর্থ deployment কী করে?

Failure Scenario

  • নতুন Docker image build হয় কিন্তু Nginx নেই (উদাহরণে Ubuntu দিয়ে replace করা হয়)।
  • ECS নতুন task launch করে, ALB target group-এ register করার চেষ্টা করে।
  • Health check fail করে কারণ HTTP respond করতে পারছে না।
  • ECS service task deregister করে, আবার নতুন task launch করে।
  • এটি infinite loop — circuit breaker ছাড়া ECS নিজে থেকে থামে না।
Circuit breaker ছাড়া failed deployment হলে ECS forever নতুন task launch ও fail করতে থাকে। এটি দেখতে — ECS service event list-এ বারবার task start/stop event আসতে থাকে।

Stopping a Failed Pipeline Execution

Pipeline-এর Stop execution বাটন → Stop and abandon — তাৎক্ষণিকভাবে execution fail করে mark করে। কিন্তু ECS deployment নিজে থেকে থামে না।

Fix করতে: Dockerfile ঠিক করে নতুন commit push করুন → pipeline trigger হবে → নতুন successful deployment শুরু হবে → ECS primary deployment update হবে।

ECS Deployment Circuit Breaker ও Rollback

Circuit Breaker কীভাবে কাজ করে

Threshold calculation: max(10, min(200, ceil(desired_tasks / 2)))

Desired tasks = 2 হলে: ceil(2/2) = 1, কিন্তু minimum 10। তাই threshold = 10 task failures।

10টি task fail করলে ECS deployment-কে failure mark করে। Rollback enabled থাকলে previous successful deployment-কে primary করে।

Enable করার ধাপ

  1. ECS service → Edit service।
  2. Deployment failure detection → Use the Amazon ECS deployment circuit breaker enable।
  3. Rollbacks on failures enable।
  4. Update।
stateDiagram-v2 [*] --> InProgress: New deployment starts InProgress --> TaskFail: Task health check fails TaskFail --> InProgress: ECS tries replacement InProgress --> CircuitTripped: 10+ task failures CircuitTripped --> Rollback: Rollback enabled Rollback --> [*]: Previous deployment becomes primary CircuitTripped --> Failed: Rollback disabled Failed --> [*]: Service stuck, manual fix needed

ECS deployment circuit breaker flow।

Rollback enabled থাকলে failed deployment শেষে ECS পুরনো successful deployment-কে primary করে — service scale করতে পারে। Rollback disabled থাকলে failed deployment primary-ই থাকে — scale out করা যায় না।

Min ও Max Running Tasks

SettingDefaultমানেRounding
Minimum running tasks100%Deployment-এর সময় minimum এই % task serving থাকবেRound UP
Maximum running tasks200%Deployment-এর সময় maximum এই % পর্যন্ত task চলতে পারবেRound DOWN

উদাহরণ: 3 tasks, 50% min, 150% max

  • Min: ceil(3 × 0.5) = ceil(1.5) = 2 tasks সবসময় running।
  • Max: floor(3 × 1.5) = floor(4.5) = 4 tasks maximum।
  • পার্থক্য: 4-3=1 replacement task একসাথে launch → 3-2=1 original task একসাথে stop।
  • Rolling deployment: একটি একটি করে replace — সত্যিকারের rolling।

Default 100%/200% (2 tasks)

  • Min: 2 tasks সবসময় running।
  • Max: 4 tasks। সব 2 replacement একসাথে launch, তারপর সব 2 পুরনো stop।
  • Blue/Green-এর মতো দেখায় — AWS এটিকে rolling বলে।

ASG Capacity Provider-এ ECS Service

Fargate-এর পরিবর্তে EC2 container instances-এ ECS service deploy করা যায়।

ASG Scaling Mechanism

  • Scale out: Task launch দরকার কিন্তু capacity নেই → 1 মিনিট পর CloudWatch alarm trigger → ASG scale out।
  • Scale in: 15 মিনিট idle capacity থাকলে → alarm trigger → idle instance terminate।

Managed Instance Protection

Scale-in-এ active task-সহ instance terminate না হওয়ার জন্য enable করুন:

  1. ECS Cluster → Capacity Providers tab → Auto Scaling Group provider নির্বাচন → Update।
  2. Managed termination protection enable।
ASG capacity provider ব্যবহার করলে deployment-এর আগে নিশ্চিত করুন যে maximum capacity limit reach হয়নি। না হলে নতুন task provisioning state-এ আটকে থাকবে।

নিজেকে যাচাই করুন

১. CodeBuild-এ Docker image build করতে কোন বিশেষ setting enable করতে হবে এবং কেন?

Privileged mode enable করতে হবে। CodeBuild নিজেই একটি Docker container-এ চলে। Docker-in-Docker (Docker daemon access) করতে privileged mode দরকার — না হলে docker build command fail করে।

২. imagedefinitions.json file-এ কী থাকে এবং কে তৈরি করে?

Format:

[{"name":"CONTAINER_NAME","imageUri":"ECR_IMAGE_URI"}]

name = task definition-এর container name। imageUri = নতুন image URI।

CodeBuild project buildspec-এর post_build phase-এ printf command দিয়ে তৈরি করে এবং artifact হিসেবে export করে। ECS deploy action এটি পড়ে নতুন task definition revision তৈরি করে।

৩. ECS deployment circuit breaker-এর threshold কীভাবে calculate হয়? 2 tasks-এর service-এ কত?

Formula: max(10, min(200, ceil(desired_tasks / 2)))

2 tasks: ceil(2/2) = 1, কিন্তু minimum 10। তাই threshold = 10 task failures।

10টি task fail করার পরেই circuit breaker trigger হবে।

৪. ECR Public Gallery-তে Docker official images-এর URI format কী?

public.ecr.aws/docker/library/IMAGE_NAME:TAG

উদাহরণ: public.ecr.aws/docker/library/node:20

Login command: aws ecr-public get-login-password --region us-east-1 | docker login --username AWS --password-stdin public.ecr.aws

Region অবশ্যই us-east-1 হতে হবে।

৫. CODEBUILD_RESOLVED_SOURCE_VERSION environment variable-এ কী থাকে এবং image tag হিসেবে শুধু প্রথম 8 characters কীভাবে নেবেন?

এই variable-এ 40-character Git commit ID থাকে। CodePipeline Git source থেকে এটি pass করে।

Bash substring syntax:

${CODEBUILD_RESOLVED_SOURCE_VERSION:0:8}

Format: ${VAR:START_INDEX:LENGTH} — index 0 থেকে 8 characters।
