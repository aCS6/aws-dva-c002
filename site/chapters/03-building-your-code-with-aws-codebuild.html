এই চ্যাপ্টারে যা শিখবেন

  • AWS CodeBuild কী — serverless, managed build service এবং এর মূল concepts।
  • CodeBuild project তৈরি করা: image selection, compute size, service role, buildspec configuration।
  • buildspec.yml file তৈরি করা: version, phases (install, pre_build, build, post_build), artifacts।
  • Build execution lifecycle-এর সব phases: SUBMITTED → QUEUED → PROVISIONING → DOWNLOAD_SOURCE → INSTALL → PRE_BUILD → BUILD → POST_BUILD → UPLOAD_ARTIFACTS → FINALIZING → COMPLETED।
  • Build failure হলে CloudWatch Logs এবং CodeBuild Console-এ log দেখার পদ্ধতি।
  • finally block-এর ব্যবহার।
  • Automated test না থাকলে broken code deploy হওয়ার risk।
  • Pipeline-এ separate test action যোগ করা — sequential action group ব্যবহার করে।

AWS CodeBuild কী?

AWS CodeBuild হলো AWS Developer Tools family-র একটি fully managed, serverless build service। আপনি build server maintain করেন না — শুধু build specification দেন।

মূল বৈশিষ্ট্য

  • Serverless ও Managed: Build server প্রভিশন, patch বা scale করার দরকার নেই।
  • Scalable: Build demand অনুযায়ী automatically scale করে।
  • Cost-effective: শুধুমাত্র build container চলার সময় pay করতে হয়। Idle time-এ কোনো cost নেই।
  • Docker-based: প্রতিটি build-এর জন্য একটি নতুন Docker container provision করা হয়।

CodeBuild কীভাবে কাজ করে

CodeBuild-কে pipeline-এর মধ্যে একটি command-line tool হিসেবে ভাবুন — যেকোনো shell command execute করতে পারে। Build করা, test run করা, Docker image build করা — সব কিছু।

flowchart LR SOURCE["Source Artifact\n(from S3 artifact store)"] --> CB["AWS CodeBuild\nDocker Container"] CB -->|reads| BS["buildspec.yml\n(in source code)"] BS --> PHASES["Install → Pre_build\n→ Build → Post_build"] PHASES --> ART["Build Artifact\n(to S3 artifact store)"] ART --> DEPLOY["Deploy Stage"] PHASES -.->|logs| CW["CloudWatch Logs"]

CodeBuild-এর মূল flow: source artifact → Docker container → buildspec → build artifact।

Build Image Options

CodeBuild-এ দুই ধরনের image ব্যবহার করা যায়:

  • CodeBuild-managed images: AWS-এর তৈরি standard image — Ubuntu, Amazon Linux 2, Windows Server Core। এগুলো runtime (Node.js, Python, Java, .NET, Ruby, Go) সহ আসে।
  • Custom Docker image: Docker Hub বা Amazon ECR-এর যেকোনো image।

Compute Options

  • EC2 compute (standard): সব region-এ supported, সব standard image।
  • AWS Lambda compute: শুধুমাত্র কিছু region-এ supported।

Security

  • Data in transit: SSL certificates + Signature Version 4 signing।
  • Data at rest: S3 artifacts, logs, cache — AWS KMS customer-managed key দিয়ে encrypted।
  • Access control: IAM service role দিয়ে CodeBuild project চালানোর permission নির্ধারণ।

Standalone vs Pipeline-integrated

CodeBuild standalone-ও ব্যবহার করা যায়:

  • Source: CodeCommit, S3, GitHub, Bitbucket থেকে directly pull করতে পারে।
  • Console, CLI বা SDK দিয়ে manually trigger করা যায়।
  • CloudWatch Events দিয়ে scheduled build (hourly, nightly) করা যায়।

Repository ও Deployment Bucket প্রস্তুত করা

এই section-এ একটি Angular application ব্যবহার করা হয়েছে — Angular জানা দরকার নেই। এটি শুধু CodeBuild concept প্র্যাকটিস করার জন্য।

GitHub Repository Setup

  1. GitHub-এ নতুন private repository তৈরি করুন: my-angular-repo
  2. Course resource থেকে my-angular-project.zip download করে extract করুন।
  3. Terminal-এ project folder-এ যান:
# Remote repository যোগ করুন
git remote add origin https://github.com/YOUR-USERNAME/my-angular-repo.git

# Push করুন (initial commit ইতিমধ্যে তৈরি)
git push origin master

S3 Deployment Bucket Setup

  1. S3-তে নতুন bucket তৈরি করুন: my-angular-website-<suffix> (Europe Ireland region)।
  2. Block all public access বন্ধ করুন।
  3. Bucket policy যোগ করুন (সব object publicly readable)।
  4. Static website hosting enable করুন।
    Angular SPA-র জন্য বিশেষ config: Single-page application-এ index document এবং error document উভয়ই index.html হিসেবে set করতে হবে। তাহলে যেকোনো route redirect করলে Angular handle করতে পারবে।

CodeBuild Project Configuration

  1. Project name: MyAngularBuild
  2. Description: (optional) "The build project for my Angular pipeline"
  3. Provisioning model: On-demand (cost-efficient)।
  4. Image type: Managed image।
  5. Compute type: EC2।
  6. Operating System: Ubuntu।
  7. Runtime: Standard।
  8. Image: aws/codebuild/standard:7.0

  9. Image version: Always use the latest — security patches ও performance benefits।
  10. Service role: New service role তৈরি করুন।

buildspec.yml তৈরি করা

buildspec.yml হলো YAML format-এর একটি specification file যা CodeBuild-কে বলে কীভাবে code build করতে হবে। এটি source code-এর root-এ রাখা হয়।

Best Practice: Buildspec সবসময় source code-এর সাথে Git repository-তে রাখুন। এতে buildspec-এর পরিবর্তন Git-এ track করা যায়।

Buildspec Structure

version: 0.2

phases:
  install:
    runtime-versions:
      nodejs: 20
    commands:
      - npm install -g @angular/cli@17

  pre_build:
    commands:
      - npm install

  build:
    commands:
      - ng build -c production
    finally:
      - echo "Build phase finished (success or failure)"

artifacts:
  base-directory: dist/my-angular-project
  files:
    - "**/*"

Phases-এর ব্যাখ্যা

Phase উদ্দেশ্য Best Practice
install Runtime version এবং build tools install Runtime version ও framework install (Angular CLI, Maven, etc.)
pre_build Build-এর আগের কাজ Project dependencies install (npm install, pip install), ECR login
build মূল build command Main build command (ng build, mvn package, docker build), test command-ও এখানে রাখা যায়
post_build Build-এর পরের কাজ Docker image push to ECR, SNS notification, cleanup

সব phase optional, কিন্তু কমপক্ষে একটি phase অবশ্যই থাকতে হবে।

runtime-versions Syntax

Runtime version define করার syntax (Ubuntu standard ও Amazon Linux 2 standard image-এ supported):

runtime-versions:
  nodejs: 20      # নির্দিষ্ট major version
  nodejs: 20.x    # major version-এর latest minor
  nodejs: latest  # সর্বশেষ version (ভবিষ্যতে পরিবর্তন হতে পারে)

Runtime key-গুলো lowercase: nodejs, python, java, ruby, dotnet ইত্যাদি।

Runtime version এবং CodeBuild image version-এর compatibility নিশ্চিত করুন। Node.js 20 শুধুমাত্র Ubuntu standard:7.0 বা তার পরের version-এ supported।

finally Block

finally key-এর অধীনে commands গুলো phase succeed বা fail যাই হোক না কেন execute হয়।

build:
  commands:
    - ng build -c production
  finally:
    - echo "This always runs"
    - aws sns publish --topic-arn $SNS_TOPIC --message "Build complete"
finally block-এর কোনো command fail করলেও পুরো phase fail হিসেবে চিহ্নিত হবে — এমনকি main commands succeed করলেও।

artifacts Section

artifacts:
  base-directory: dist/my-angular-project   # build output folder
  files:
    - "**/*"     # সব file ও subfolder recursively

Artifacts না থাকলেও upload_artifacts phase চলে — কিন্তু কিছু upload হয় না।

Buildspec commit ও pipeline trigger

git add .
git commit -m "Add the buildspec file"
git push origin master

Push হলে pipeline trigger হবে এবং এবার build সফল হবে।

Build-এর Lifecycle

প্রতিটি CodeBuild execution নিচের phases-এর মধ্য দিয়ে যায়:

stateDiagram-v2 [*] --> SUBMITTED SUBMITTED --> QUEUED QUEUED --> PROVISIONING PROVISIONING --> DOWNLOAD_SOURCE DOWNLOAD_SOURCE --> INSTALL INSTALL --> PRE_BUILD PRE_BUILD --> BUILD BUILD --> POST_BUILD POST_BUILD --> UPLOAD_ARTIFACTS UPLOAD_ARTIFACTS --> FINALIZING FINALIZING --> COMPLETED DOWNLOAD_SOURCE --> FINALIZING : Build fails before BUILD phase BUILD --> POST_BUILD : Even on failure

CodeBuild execution lifecycle: সফল build-এর সম্পূর্ণ phase flow এবং failure-এ shortcut path।

Phaseকী হয়
SUBMITTEDCodePipeline CodeBuild-এ build request পাঠায়।
QUEUEDConcurrent build limit পূর্ণ থাকলে queue-এ অপেক্ষা। Queued timeout পার হলে fail।
PROVISIONINGBuild image থেকে নতুন Docker container provision করা হয়।
DOWNLOAD_SOURCES3 artifact store থেকে source artifact download, buildspec parse, runtime version install।
INSTALLinstall phase-এর commands execute।
PRE_BUILDpre_build phase-এর commands execute।
BUILDbuild phase-এর commands execute।
POST_BUILDpost_build phase-এর commands execute। BUILD fail করলেও চলে।
UPLOAD_ARTIFACTSBuild artifact S3 artifact store-এ upload। POST_BUILD fail করলেও চলে।
FINALIZINGContainer teardown, internal cleanup।
COMPLETEDExecution শেষ — SUCCESS বা FAILED।

Failure Behavior

  • BUILD phase-এর আগে fail করলে: সরাসরি FINALIZING-এ যায় (POST_BUILD, UPLOAD_ARTIFACTS skip)।
  • BUILD phase-এ fail করলে: POST_BUILD এবং UPLOAD_ARTIFACTS তবুও চলে।
  • POST_BUILD fail করলে: Build artifact upload হতে পারে কিন্তু pipeline-এর পরবর্তী action trigger হবে না।

Build Failure Logs দেখা

Build failure debug করতে তিনটি জায়গা থেকে log দেখা যায়:

১. CodePipeline Action Details

  1. Pipeline-এ failed build action-এর View details ক্লিক করুন।
  2. Logs tab-এ build log দেখুন।
  3. এখানে real-time log streaming দেখা যায় — চলমান execution-এও।

২. AWS CodeBuild Console

  1. Action details-এ View in CodeBuild link ক্লিক করুন।
  2. Build logs tab বা Tail logs button ব্যবহার করুন।
  3. Phase details tab-এ প্রতিটি phase-এর status ও duration দেখুন।

৩. Amazon CloudWatch Logs

  1. CodeBuild Console-এ View entire log link ক্লিক করুন।
  2. Log group: /aws/codebuild/MyAngularBuild (project name থেকে generated)।
  3. Log stream ID = build execution ID।

CloudWatch Logs-এ long-term log retention, filtering এবং alerts configure করা যায়।

Build Failure সিমুলেট ও Log Analysis

Build fail হলে log-এ নিচের বিষয়গুলো দেখুন:

  • কোন phase-এ fail করেছে।
  • Error message এবং failed command।
  • finally block-এর output।
  • upload_artifacts phase-এ error থাকলে — আসল কারণ আগের phase-এ খুঁজুন।
exit 1 command দিলে Bash-এ non-zero exit code হয়, যা build failure trigger করে। Test করতে buildspec-এ এই command যোগ করে দেখুন।

Automated Test কেন দরকার?

Build ও deploy stage সফল হলেও application-এর logic ভুল হতে পারে। একটি উদাহরণ: Calculator application-এ ভুলবশত + operator-এর calculation পরিবর্তন হয়ে / হয়ে গেলে — build succeed করে deploy হয়, কিন্তু application broken।

Build ও deploy সফল হওয়া মানে application সঠিকভাবে কাজ করছে তা নয়। Application logic verify করতে automated test দরকার।

Automated Test-এর উপকারিতা

  • Deployment-এর আগেই bug ধরা পড়ে।
  • Manual testing-এর উপর নির্ভরশীলতা কমে।
  • Broken version production-এ যায় না।
  • Developer-রা নিশ্চিন্তে refactor করতে পারে।

Test Integration করার দুটি পদ্ধতি

  1. Buildspec-এ test command: Build command-এর আগে test command রাখুন। সহজ কিন্তু test fail করলে build ও skip হয়।
  2. Separate test action: Build stage-এ আলাদা sequential action group-এ test action যোগ করুন। Test fail হলে unnecessary build execute হয় না।

CodeBuild দিয়ে Test Action যোগ করা

Unit Test Buildspec তৈরি করা

Test-এর জন্য আলাদা buildspec file তৈরি করুন: unit-test-buildspec.yml

version: 0.2

phases:
  install:
    runtime-versions:
      nodejs: 20
    commands:
      - npm install -g @angular/cli@17
      # Install Headless Chrome for Angular tests
      - wget -q -O - https://dl.google.com/linux/linux_signing_key.pub | apt-key add -
      - echo "deb [arch=amd64] http://dl.google.com/linux/chrome/deb/ stable main" >> /etc/apt/sources.list.d/google.list
      - apt-get update
      - apt-get install -y google-chrome-stable

  pre_build:
    commands:
      - npm install

  build:
    commands:
      - ng test --no-watch --no-progress --browsers ChromeHeadlessCI

Test action-এ কোনো artifacts section দরকার নেই — শুধু test চালানো হয়।

Chrome Headless-এর প্রয়োজনীয়তা: Angular CLI-এর ng test command Karma test runner ব্যবহার করে, যার browser দরকার। CodeBuild-এর standard Ubuntu image-এ Chrome নেই, তাই manually install করতে হয়। ChromeHeadlessCI browser configuration-টি Angular project-এ আগে থেকে configured থাকলে এই command কাজ করবে।

Pipeline-এ Test Action যোগ করা

  1. Pipeline → Edit → Build stage-এর Edit stage।
  2. বিদ্যমান Build action-এর আগে নতুন action group-এ action যোগ করতে Add action group ক্লিক করুন (sequential)।
  3. Action name: UnitTest
  4. Action provider: Test → AWS CodeBuild

    ⚠️ Test action-এর provider বিভিন্ন — Build এর মতো "Build" group নয়, "Test" group থেকে CodeBuild নির্বাচন করুন।

  5. Input artifact: SourceArtifact (unit tests source code-এ থাকে।)
  6. Create project → CodeBuild project:
    • Name: AngularUnitTest
    • Environment: same as build project (Ubuntu, standard, 7.0)।
    • Service role: New role (আলাদা role — least privilege best practice)।
    • Buildspec: Use a buildspec file → filename: unit-test-buildspec.yml
      Custom buildspec filename অবশ্যই দিতে হবে। না দিলে default buildspec.yml (build action-এর buildspec) খুঁজবে।
  7. Output artifact: কোনো output দেবেন না — test action artifact produce করে না।
  8. Done → Done → Save।

Test Action Behavior

flowchart TD SRC["Source Stage"] --> UT["UnitTest Action\n(sequential, first)"] UT -->|Tests Pass| BUILD["Build Action\n(sequential, second)"] UT -->|Tests Fail| FAIL["Pipeline FAILED\nBuild NOT executed"] BUILD --> DEPLOY["Deploy Stage"]

Sequential test action: test fail করলে build ও deploy execute হয় না।

  • UnitTest action fail করলে Build action trigger হবে না — unnecessary cost বাঁচে।
  • Test fail হলে log-এ কোন test failed এবং expected vs actual value দেখা যায়।
  • Test action commit করতে হবে: git add . (নতুন buildspec file যোগ হয়েছে)।
# নতুন buildspec file add করুন
git add .
git commit -m "Version 4.0"
git push origin master

Buildspec-এর install phase-এ required runtime (Node.js, Python, Java, etc.) specify করা।
base-directory
Artifacts section-এ build output-এর local folder path।
DOWNLOAD_SOURCE phase
S3 artifact store থেকে source artifact download, buildspec parse।
PROVISIONING phase
Build image থেকে Docker container তৈরি।
UPLOAD_ARTIFACTS phase
Build output artifact S3-তে upload।
FINALIZING phase
Container teardown — build সবসময় এখানে আসে।
Privileged mode
Docker daemon access-এর জন্য — Docker image build করতে প্রয়োজন।
Queued timeout
Build queue-এ অপেক্ষার সর্বোচ্চ সময় (default 8 hours)।

সারাংশ

  • AWS CodeBuild serverless, managed — Docker container-এ build commands execute করে।
  • buildspec.yml source code-এর root-এ রাখুন — phases (install, pre_build, build, post_build) ও artifacts define করুন।
  • Build lifecycle: SUBMITTED → QUEUED → PROVISIONING → DOWNLOAD_SOURCE → INSTALL → PRE_BUILD → BUILD → POST_BUILD → UPLOAD_ARTIFACTS → FINALIZING → COMPLETED।
  • BUILD phase-এর আগে fail করলে POST_BUILD ও UPLOAD_ARTIFACTS skip হয়। BUILD phase-এ fail হলে POST_BUILD তবুও চলে।
  • Build log দেখুন: CodePipeline action details, CodeBuild Console (Phase details, Build logs, Tail logs), বা CloudWatch Logs।
  • Automated test pipeline-এ জরুরি — build succeed করলেও application broken হতে পারে।
  • Test action-এ: আলাদা buildspec file দিন, output artifact দেবেন না, sequential action group ব্যবহার করুন।

নিজেকে যাচাই করুন

১. buildspec.yml-এ install এবং pre_build phase-এর পার্থক্য কী?

install: Runtime version specify করা এবং build tool install (যেমন Angular CLI, Maven)। Runtime version এই phase-এই process হয়।

pre_build: Project-এর dependencies install করা (যেমন npm install)। Docker-এ ECR login-ও এখানে।

Technically সব command যেকোনো phase-এ রাখা যায়, কিন্তু এই convention follow করলে buildspec readable হয়।

২. Build lifecycle-এ BUILD phase fail করলে কোন phases skip হয় এবং কোনগুলো তবুও চলে?

Skip হয় না, তবুও চলে: POST_BUILD, UPLOAD_ARTIFACTS, FINALIZING।

কিন্তু: DOWNLOAD_SOURCE বা INSTALL/PRE_BUILD phase-এ fail করলে → POST_BUILD এবং UPLOAD_ARTIFACTS skip হয়, সরাসরি FINALIZING-এ যায়।

৩. Test action-এ output artifact কেন define করা হয় না?

Test action শুধু unit test run করে — কোনো deployable artifact তৈরি করে না। Artifact define করলে CodeBuild নির্দিষ্ট folder খুঁজবে এবং না পেলে UPLOAD_ARTIFACTS phase-এ fail করবে। তাই test buildspec-এ artifacts section রাখা উচিত নয়।

৪. Test action-কে build action-এর আগে sequential-এ রাখার সুবিধা কী?

Test fail করলে build action execute হবে না। ফলে:

  • Unnecessary build cost বাঁচে।
  • Broken code deploy হওয়ার chance নেই।
  • Pipeline execution দ্রুত fail করে feedback দেয়।

Parallel-এ রাখলে test fail হলেও build চলবে — cost বাড়বে।

৫. CodeBuild-এ finally block-এর একটি practical use case কী?

Build success বা failure নির্বিশেষে notification পাঠানো:

build:
  commands:
    - ng build -c production
  finally:
    - aws sns publish --topic-arn $BUILD_NOTIFY_TOPIC \
        --message "Build status: $CODEBUILD_BUILD_SUCCEEDING"

অথবা temporary file cleanup, test report upload ইত্যাদি।
