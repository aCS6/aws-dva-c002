  • Pipeline-এ CloudFormation দিয়ে automatic staging environment তৈরি ও delete করা।

  • CloudFormation Delete Stack action দিয়ে staging stack auto-cleanup।
  • Superseded execution কী, কোন condition-এ ঘটে এবং কীভাবে pipeline-কে প্রভাবিত করে।
  • Pipeline-এ notification rule তৈরি এবং existing SNS topic-এ CodeStar publish permission যোগ করা।

CloudFormation Deploy Action — Staging Stack তৈরি

CodePipeline-এ CloudFormation deploy action ব্যবহার করে প্রতিটি execution-এ একটি temporary staging environment তৈরি করা যায়। Staging-এ application test করার পর stack delete করা হয়। Production-এ deploy হয় manual approval-এর পরেই।

CloudFormation Template প্রস্তুত করা

Source code-এর root-এ cloudformation/staging-stack-template.yaml ফাইল রাখুন। Template-এ থাকা resources:

  • EC2 instance — staging web server, tag: Environment: Staging।
  • IAM instance profile — WebServerRole attach করার জন্য।
  • Security group — HTTP (80) access allow।

Template parameters:

  • WebServerImage — staging instance-এর AMI ID (previously created web-server-ami)।
  • WebServerRoleName — attach করার IAM role-এর নাম।

Template output: WebServerDnsName — staging instance-এর public DNS name।

CloudFormation Service Role তৈরি

  1. IAM Console → Create role।
  2. Use case: CloudFormation।
  3. Policies: AmazonEC2FullAccess + IAMFullAccess।

    ⚠️ Full access policy উদাহরণের জন্য। Production-এ শুধু প্রয়োজনীয় specific permissions দিন।

  4. Role name: CloudFormationServiceRoleForMyPipeline

Pipeline-এ CloudFormation Action যোগ করার ধাপ

  1. Pipeline → Edit → Build ও Deploy stage-এর মাঝে Add stage → নাম: Staging।
  2. Staging stage-এ Add action group।
  3. Action name: CreateStagingStack
  4. Action provider: AWS CloudFormation (Deploy group-এ)।
  5. Input artifacts: SourceArtifact — template source code-এ আছে।
  6. Action mode: Replace a failed stack।
  7. Stack name: StagingStack
  8. Template: Artifact = SourceArtifact, File = cloudformation/staging-stack-template.yaml
  9. Capabilities: CAPABILITY_IAM — template-এ IAM resource (instance profile) আছে।
  10. Role name: CloudFormationServiceRoleForMyPipeline
  11. Advanced → Parameter overrides (JSON):
{
  "WebServerImage": "ami-xxxxxxxxxxxxxxxxx",
  "WebServerRoleName": "WebServerRole"
}

AMI ID: EC2 Console → AMIs → আপনার web-server-ami-এর ID কপি করুন।

CloudFormation Action Modes

Modeআচরণকখন ব্যবহার করবেন
Create or update a stackনেই → create। আছে → update।Staging/production stack manage।
Replace a failed stackCreate/update-এর মতো + FAILED state-এর stack replace।Staging environment — failed stack-ও recover।
Delete a stackStack delete। না থাকলে fail করে না।Staging cleanup।
Create or replace a change setStack-এ কী পরিবর্তন হবে তার preview।Production infra — apply-এর আগে review।
Execute a change setআগে তৈরি change set apply করে।Change set approve করার পরে।
Production infrastructure pipeline best practice:
Create/Replace Change Set → Manual Approval → Execute Change Set। এতে infra পরিবর্তন review করে approve করা যায়।

CloudFormation Stack Status দেখা

Pipeline action-এর Details link ক্লিক করলে CloudFormation Console-এ stack details খোলে। Events tab-এ resource creation progress, Resources tab-এ created resources দেখা যায়। Stack-এর Outputs tab-এ exported values (যেমন DNS name) থাকে।

Staging-এ CodeDeploy Deploy Action

CloudFormation stack তৈরির পরে staging instance-এ application deploy করতে একটি আলাদা CodeDeploy deployment group দরকার।

Staging Deployment Group তৈরি

  1. CodeDeploy Console → Application → Create deployment group।
  2. Name: StagingInstances
  3. Service role: CodeDeployEC2ServiceRole
  4. Deployment type: In-place।
  5. Environment: Amazon EC2 instances।
  6. Tag: Key=Environment, Value=Staging (CloudFormation template-এ assign করা tag-এর সাথে match করে)।
  7. Deployment config: AllAtOnce।
  8. Load balancer: Disable।
  9. Rollbacks: Disable — staging instance temporary, rollback দরকার নেই।

Pipeline-এ DeployToStaging Action যোগ করা

  1. Staging stage → Edit stage → CreateStagingStack-এর পরে Add action group।
  2. Action name: DeployToStaging
  3. Action provider: AWS CodeDeploy।
  4. Input artifact: BuildArtifact।
  5. Application: MyAngularApp, Deployment group: StagingInstances।

Staging instance-এর DNS name পেতে CloudFormation stack-এর Outputs tab দেখুন।

Manual Approval Action যোগ করা

Manual approval action pipeline execution pause করে — কেউ manually approve বা reject না করা পর্যন্ত পরবর্তী stage-এ যায় না।

SNS Topic তৈরি ও Subscribe করা

  1. Amazon SNS Console → Create topic।
  2. Topic name: PipelineNotifications
  3. Display name: Pipeline Notifications (email sender হিসেবে দেখাবে)।
  4. Create subscription → Protocol: Email → আপনার email address।
  5. AWS-এর confirmation email-এ confirm link ক্লিক করুন। Status "Confirmed" হলে ready।

Manual Approval Action কোথায় রাখবেন

আলাদা stage-এ নয়। ManualApproval action অবশ্যই Staging stage-এর ভেতরে (DeployToStaging-এর পরে) রাখুন।

কারণ: যদি আলাদা stage হয়, নতুন execution staging stage-এ enter করে পুরনো staging environment overwrite করতে পারে যখন আগের execution approval-এর অপেক্ষায়। Staging stage-এর ভেতরে রাখলে stage lock থাকে — reviewer সঠিক revision দেখতে পারে।

Manual Approval Action Configure করা

  1. Staging stage → Edit stage → DeployToStaging-এর পরে Add action group।
  2. Action name: ManualApproval
  3. Action provider: Manual approval (Approval group-এ)।
  4. SNS topic ARN: আগে তৈরি topic নির্বাচন করুন।
  5. URL for review: staging environment-এর URL (পরে action variable দিয়ে dynamic করা হবে)।
  6. Comments: Reviewer-কে দেওয়া instruction।

Manual Approval Notification Email

Approval-এর জন্য অপেক্ষা হলে email-এ পাওয়া যায়:

  • Pipeline, stage ও action name।
  • "Content to review" — staging URL।
  • "Approve or reject" — pipeline-এ direct link।
  • Custom comment।
  • Deadline: 7 days — এর মধ্যে কোনো action না নিলে execution fail হয়।

Approve ও Reject

  • Pipeline-এ ManualApproval action-এর Review বাটন ক্লিক করুন।
  • Approve → execution পরবর্তী action-এ যায়।
  • Reject → execution সেখানে fail করে থামে।
  • Comment দেওয়া ভালো practice — developer বুঝতে পারে কেন reject হলো।
sequenceDiagram participant Dev as Developer participant CP as CodePipeline participant SNS as SNS Topic participant Rev as Reviewer Dev->>CP: git push CP->>CP: Source → Build → Staging Deploy CP->>SNS: ManualApproval waiting SNS->>Rev: Email notification Rev->>Rev: Opens staging URL, reviews Rev->>CP: Approve (Review button) CP->>CP: Continue to Production Deploy

Manual Approval flow: staging deploy → SNS notification → reviewer approves → production deploy।

Action Variables ও Variable Namespace

সমস্যা: Static URL

ManualApproval action-এ staging URL static হিসেবে দেওয়া হয়েছিল। CloudFormation stack delete ও recreate হলে নতুন DNS name assign হয় — URL invalid হয়ে যায়।

সমাধান: Action Variables

CloudFormation deploy action stack-এর Outputs-কে action variable হিসেবে export করে। পরবর্তী action সেই variable reference করতে পারে।

Configure করার ধাপ

  1. CreateStagingStack action edit করুন।
  2. Variable namespace দিন: StagingStackVariables
  3. ManualApproval action edit করুন।
  4. URL for review field-এ:
http://#{StagingStackVariables.WebServerDnsName}

Variable Reference Syntax

#{NamespaceName.VariableName}
Action TypeNamespace Exampleউদাহরণ Variable
CloudFormationStagingStackVariables#{StagingStackVariables.WebServerDnsName}
Source (GitHub)SourceVariables#{SourceVariables.CommitId}, #{SourceVariables.BranchName}
Source (S3)SourceVariables#{SourceVariables.ETag}, #{SourceVariables.VersionId}
Manual ApprovalApprovalVariables#{ApprovalVariables.ApproverArn}

Action variable: CloudFormation stack output → ManualApproval URL-এ dynamic reference।

Execution details-এ কোনো action-এর Output variables section দেখুন — সব exported variable ও তাদের মান দেখা যাবে।

CloudFormation Delete Stack Action

Manual approval-এর পরে staging stack আর দরকার নেই। Pipeline-এ Delete Stack action যোগ করে automatic cleanup করা যায়।

DeleteStagingStack Action Configure করা

  1. Staging stage → Edit stage → ManualApproval-এর পরে Add action group।
  2. Action name: DeleteStagingStack
  3. Action provider: AWS CloudFormation।
  4. Input artifacts: খালি রাখুন — delete করতে template দরকার নেই।
  5. Action mode: Delete a stack।
  6. Stack name: StagingStack।
  7. Role: CloudFormationServiceRoleForMyPipeline।
Manual Approval reject করলে execution সেখানে fail হয়ে থামে — DeleteStagingStack action-এ পৌঁছায় না। Staging stack তখনো থাকে — developer সেটি দেখে সমস্যা debug করতে পারে। Staging stack manually delete করতে হবে।

Superseded Pipeline Executions

একই সময়ে একাধিক execution pipeline-এ থাকলে একটি execution আরেকটিকে supersede করতে পারে।

Superseded কী?

যখন কোনো পুরনো execution দুটি stage-এর মাঝখানে (transition-এ) অপেক্ষা করছে, এবং একটি নতুন execution সেখানে এসে পৌঁছায়, তখন পুরনো execution Superseded state-এ চলে যায় এবং জীবনচক্র শেষ করে।

Key Rule

  • কোনো execution stage-এ enter করলে সেটিকে supersede করা যায় না — stage lock হয়ে যায়।
  • Superseding শুধুমাত্র stage-এর বাইরে (দুটি stage-এর transition-এ) ঘটে।

Example: 3 Concurrent Executions

flowchart LR subgraph Timeline direction TB E1["Exec 1 (v14.1)\nSource ✅ Build ✅\nStaging: locked at ManualApproval"] E2["Exec 2 (v14.2)\nSource ✅ Build ✅\nWaiting at transition"] E3["Exec 3 (v14.3)\nSource ✅ Build ✅\nCatches up to E2!"] end E3 -->|supersedes| E2 E2 --> SUPERSEDED["Exec 2: SUPERSEDED\n(never entered Staging)"] E1 -->|Approved| PROD1["Exec 1 → Production"] E3 -->|Next to enter Staging| STAG3["Exec 3 → Staging → Production"]

Exec 2 superseded হয় — Staging stage-এ ঢোকার আগেই Exec 3 catch up করে।

Pipeline history-তে superseded execution-এর status Superseded দেখায়। Superseded execution-এ যে stage পর্যন্ত পৌঁছাতে পারেনি সেই stage-এর actions execute হয়নি।

Real-world benefit: Developer দ্রুত পরপর অনেক commit push করলে মাঝের versions staging-এ deploy না হয়ে skip হয়ে যায়। শুধু latest version staging-এ যায় — অপ্রয়োজনীয় staging resource তৈরি হয় না, সময় ও cost বাঁচে।

Pipeline Notification Rules

Pipeline execution-এর status change হলে SNS-এর মাধ্যমে notification পাঠানো যায়।

Notification Types

Event Categoryকী notify করেRecommended?
Pipeline execution statesStarted, Succeeded, Failed, Superseded, etc.✅ হ্যাঁ
Stage execution statesপ্রতিটি stage-এর status change❌ অনেক email
Action execution statesপ্রতিটি action-এর status change❌ অনেক বেশি

Notification Rule তৈরি (সহজ পদ্ধতি — নতুন SNS topic)

  1. Pipeline → Settings → Notifications tab → Create notification rule।
  2. Rule name: PipelineNotificationsRule
  3. Detail type: Full।
  4. Events: Pipeline execution states (Started, Succeeded, Failed, Superseded)।
  5. Target: Create target বাটনে নতুন SNS topic তৈরি করুন — policy automatically configure হবে।
  6. Email subscribe করুন।

Existing SNS Topic ব্যবহার করা (Manual Permission)

Existing topic ব্যবহার করলে topic-এর access policy-তে CodeStar-কে publish করার permission দিতে হবে।

SNS topic → Edit → Access policy-তে নিচের statement যোগ করুন:

{
  "Sid": "AWSCodeStarNotifications_publish",
  "Effect": "Allow",
  "Principal": {
    "Service": "codestar-notifications.amazonaws.com"
  },
  "Action": "SNS:Publish",
  "Resource": "arn:aws:sns:REGION:ACCOUNT-ID:TOPIC-NAME"
}
কেন CodeStar? AWS Developer Tools-এর built-in notification feature CodeStar Notifications service ব্যবহার করে — এটি একটি separate service principal। Pipeline-এর service role-এর permission এখানে apply হয় না।

Notification Format

  • Pipeline notification (JSON format): execution ID, pipeline name, state, region ইত্যাদি। Third-party integration-এ উপযুক্ত।
  • Manual Approval notification (text format): Human-readable, review URL ও approve/reject link সহ।

সারাংশ

  • Template-এ IAM resource থাকলে CAPABILITY_IAM capability অবশ্যই দিতে হবে।

নিজেকে যাচাই করুন

১. CloudFormation template-এ IAM resource থাকলে pipeline action-এ কী বাড়তি configuration দিতে হয়?

CloudFormation deploy action-এর Capabilities section-এ CAPABILITY_IAM নির্বাচন করতে হবে। এটি না দিলে CloudFormation stack creation fail করবে কারণ IAM resource তৈরিতে explicit acknowledgment প্রয়োজন।

২. Manual Approval action কেন আলাদা stage-এ না রেখে Staging stage-এর ভেতরে রাখা উচিত?

আলাদা stage-এ রাখলে নতুন execution Staging stage-এ enter করতে পারে এবং staging environment overwrite করতে পারে যখন পুরনো execution approval-এর অপেক্ষায়। Staging stage-এর ভেতরে রাখলে সেই stage lock থাকে — reviewer সঠিক revision-ই দেখতে পাবে।

৩. Action variable syntax কী এবং CloudFormation output কীভাবে ManualApproval-এ ব্যবহার করবেন?

Syntax: #{NamespaceName.VariableName}

Steps:

  1. CreateStagingStack action-এ Variable namespace দিন: StagingStackVariables
  2. ManualApproval-এর URL for review field-এ: http://#{StagingStackVariables.WebServerDnsName}

এখন প্রতিটি execution-এ নতুন staging DNS name automatically URL-এ inject হবে।

৪. Superseded execution কখন ঘটে? Stage lock হয়ে থাকলে কি supersede হয়?

Superseded ঘটে যখন কোনো execution দুটি stage-এর মাঝে (transition-এ) অপেক্ষা করছে এবং নতুন execution সেখানে এসে পৌঁছায়।

Stage lock হয়ে গেলে (execution stage-এ enter করলে) supersede হয় না — lock remove না হওয়া পর্যন্ত নতুন execution বাইরে অপেক্ষা করে।

৫. Existing SNS topic-এ pipeline notification পাঠাতে কোন permission দিতে হবে এবং কেন pipeline service role কাজ করে না?

SNS topic-এর access policy-তে codestar-notifications.amazonaws.com service principal-কে SNS:Publish permission দিতে হবে।

Pipeline service role কাজ করে না কারণ notification AWS CodeStar Notifications service-এর মাধ্যমে পাঠানো হয় — এটি একটি separate AWS service principal, pipeline-এর IAM role নয়।
