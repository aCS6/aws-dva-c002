AWS CodeDeploy কী?

AWS CodeDeploy হলো AWS-এর automated application deployment service। এটি AWS Developer Tools family-র সদস্য — managed ও scalable।

কোথায় Deploy করা যায়

  • Amazon EC2 instances: Single instance বা ASG + ALB-এর পেছনে multiple instances।
  • On-premises instances: AWS-এর বাইরের নিজস্ব সার্ভার।
  • AWS Lambda functions: Serverless deployment।
  • Amazon ECS: Container deployment।

সুবিধা

  • Automation: Manual deployment process (SSH → command run) বাদ দেয়, human error কমায়।
  • Minimum downtime: Rolling deployment-এ একবারে কয়েকটি instance নিয়ে deploy করা যায়।
  • Blue/Green deployment: নতুন instance-এ deploy করে traffic switch করা — production প্রায় unaffected থাকে।
  • Automated rollback: Failure হলে automatically পূর্ববর্তী successful revision deploy করে।
  • Traffic shifting (Lambda/ECS): Canary, linear বা all-at-once traffic shift।

EC2 Instance-এর সাথে CodeDeploy কীভাবে কাজ করে

CodeDeploy EC2 instance-কে directly access করে না। পরিবর্তে:

  1. EC2 instance-এ CodeDeploy agent installed ও running থাকে।
  2. Agent প্রতি সেকেন্ডে CodeDeploy service poll করে নতুন deployment আছে কিনা।
  3. নতুন deployment থাকলে agent CodeDeploy-এর দেওয়া S3 URL থেকে revision download করে।
  4. Agent appspec.yml অনুযায়ী deployment execute করে।

এই কারণে EC2 instance-এ অবশ্যই S3-তে access-এর IAM permission থাকতে হবে।

CodeDeploy Concepts

Application
CodeDeploy-এর top-level component। একটি application নির্দিষ্ট compute platform-এর জন্য — EC2/On-premises, Lambda, বা ECS। একই application দিয়ে একাধিক platform-এ deploy করা যায় না।
Compute Platform
EC2/On-premises, Lambda, বা ECS। Application type নির্ধারণ করে।
Deployment Group
কোথায় deploy হবে তা define করে। Tagged EC2 instances বা ASG হতে পারে।
Deployment Configuration
Deployment-এর success/failure rule। যেমন: AllAtOnce, HalfAtATime, OneAtATime। Custom configuration-ও তৈরি করা যায়।
Revision
কী deploy হবে তা — deployable source code, appspec file এবং deployment scripts সহ।
Deployment
একটি revision-কে একটি deployment group-এ execute করা। Build-এর মতো CodeBuild-এ।
Appspec file
CodeDeploy-এর deployment specification file (YAML বা JSON)। EC2-তে: appspec.yml। ECS/Lambda-তে: appspec.yaml। Source code-এর root-এ থাকতে হবে, path customizable নয়।
Appspec file naming: EC2-তে appspec.yml (yml extension)। Lambda/ECS-তে appspec.yaml (yaml extension)। দুটো ভিন্ন!

EC2 Instance-এর জন্য IAM Role

EC2 Instance IAM Role (WebServerRole)

EC2 instance-কে CodeDeploy artifact store (S3) থেকে revision download করার permission দরকার।

  1. IAM Console → Roles → Create role।
  2. Use case: EC2।
  3. Policy: AmazonEC2RoleforAWSCodeDeploy managed policy।

    এই policy EC2 instance-কে সব S3 bucket-এ GetObject ও ListBucket permission দেয়। Production-এ শুধু artifact store bucket-এ সীমাবদ্ধ করা উচিত।

  4. Role name: WebServerRole

CodeDeploy Service Role (CodeDeployEC2ServiceRole)

CodeDeploy service role EC2 tag দেখতে, ASG manage করতে এবং ALB-এ register/deregister করতে ব্যবহার হয়। Deployment group তৈরিতে এই role দিতে হয়।

  1. IAM Console → Roles → Create role।
  2. Use case: CodeDeploy → CodeDeploy (EC2/On-premises use case)।
  3. Policy: AWSCodeDeployRole — EC2 tags expand, ASG ও ELB access।
  4. Role name: CodeDeployEC2ServiceRole
  5. Blue/Green deployment-এর জন্য additional inline policy যোগ করুন:
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ec2:RunInstances",
        "ec2:CreateTags",
        "iam:PassRole"
      ],
      "Resource": "*"
    }
  ]
}

EC2 Instance Configure করা

EC2 Launch Configuration

  • AMI: Amazon Linux 2 (Amazon Linux 2023 নয়)।
  • Instance type: t2.micro (free tier)।
  • IAM instance profile: WebServerRole।
  • Security group: SSH (port 22) + HTTP (port 80) open।
  • Tag: Application = MyAngularProject (CodeDeploy deployment group-এর জন্য)।

EC2 Instance Connect করে Setup

# ১. Package update
sudo yum update -y

# ২. Dependencies install
sudo yum install -y ruby wget

# ৩. CodeDeploy agent download (Ireland region)
wget https://aws-codedeploy-eu-west-1.s3.eu-west-1.amazonaws.com/latest/install

# ৪. Executable করুন
chmod +x ./install

# ৫. Agent install করুন
sudo ./install auto

# ৬. Status check

CodeDeploy agent download URL-এ region code থাকে। আপনার region অনুযায়ী পরিবর্তন করুন। যেমন us-east-1 হলে: aws-codedeploy-us-east-1.s3.us-east-1.amazonaws.com

Nginx Web Server Install ও Configure

# Nginx install (Amazon Linux 2-এ Amazon Extras ব্যবহার করুন)
sudo amazon-linux-extras install -y nginx1

# Nginx start করুন
sudo service nginx start

# Boot-এ auto-start enable করুন
sudo chkconfig nginx on

# Status check
sudo service nginx status

Nginx configuration file edit করে Angular project folder serve করুন:

# Nginx config file edit
sudo nano /etc/nginx/nginx.conf

# server block-এ root directive পরিবর্তন করুন:
root /var/www/my-angular-project;

# Nginx restart
sudo service nginx restart
# Application folder তৈরি করুন
sudo mkdir -p /var/www/my-angular-project
CodeDeploy agent-এর deployment folder empty থাকতে হবে। আগে অন্য deployment group থেকে deploy করা files থাকলে error হবে।

Tagged EC2-এর জন্য Deployment Group

CodeDeploy Application তৈরি

  1. CodeDeploy Console → Applications → Create application।
  2. Application name: MyAngularApp
  3. Compute platform: EC2/On-premises।

Deployment Group তৈরি

  1. Application-এ → Create deployment group।
  2. Group name: TaggedEC2Instances
  3. Service role: CodeDeployEC2ServiceRole
  4. Deployment type: In-place।
  5. Environment configuration: Amazon EC2 instances।
  6. Tag group: Key=Application, Value=MyAngularProject
    Tag group-এর logic:
    • একই tag group-এর মধ্যে একাধিক tag = OR operator।
    • ভিন্ন tag group = AND operator — instance-কে সব group-এর অন্তত একটি tag match করতে হবে।
  7. Deployment configuration: CodeDeployDefault.AllAtOnce।
  8. Load balancer: Disable (এখন ALB নেই)।

Pipeline-এ CodeDeploy Deploy Action

  1. Pipeline → Edit → Deploy stage-এর Edit stage।
  2. পুরনো S3 deploy action remove করুন।
  3. Add action group → Action name: DeployToEC2।
  4. Action provider: AWS CodeDeploy।
  5. Input artifact: BuildArtifact (SourceArtifact নয়!)।
  6. Application name: MyAngularApp।
  7. Deployment group: আপনার group।
  8. Done → Done → Save।
Input artifact অবশ্যই BuildArtifact হতে হবে। SourceArtifact-এ appspec.yml নেই।

appspec.yml তৈরি করা

appspec.yml CodeDeploy-কে বলে deployment-এ কী করতে হবে। এটি source code-এর root-এ থাকতে হবে — এবং build artifact-এও include করতে হবে।

সম্পূর্ণ appspec.yml উদাহরণ

version: 0.0
os: linux

files:
  - source: dist/my-angular-project
    destination: /var/www/my-angular-project

permissions:
  - object: /var/www/my-angular-project
    pattern: "**"
    mode: "0755"
    owner: root
    group: root
    type:
      - file
      - directory

hooks:
  ApplicationStart:
    - location: deploy-scripts/application-start-hook.sh
      timeout: 300
  # ValidateService:
  #   - location: deploy-scripts/validate-service.sh
  #     timeout: 300

deploy-scripts/application-start-hook.sh

#!/bin/bash

sudo service nginx restart

Sections-এর ব্যাখ্যা

version
Appspec syntax version — সবসময় 0.0।
os
Target OS: linux বা windows (lowercase)।
files
Revision থেকে কোন files/folders কোথায় copy করবে। source: / মানে সব files। Source path revision-এ relative; destination EC2-তে absolute।
permissions
Deployed files/directories-এর Linux permissions সেট করা। Optional।
hooks
Deployment lifecycle events-এ shell scripts execute করার সুবিধা।

Build Artifact-এর সাথে Align করা

Buildspec-এ artifacts section-এ appspec ও deploy-scripts-ও include করতে হবে:

artifacts:
  files:
    - dist/my-angular-project/**/*
    - appspec.yml
    - deploy-scripts/**/*
base-directory remove করতে হবে যখন appspec ও scripts include করতে হয়। তাহলে appspec-এর files section-এ source: dist/my-angular-project specify করতে হবে।

Deployment Logs দেখা

# নির্দিষ্ট deployment-এর logs

# নির্দিষ্ট deployment-এর revision contents

CodeDeploy Console-এ deployment failure হলে:

  1. Deployment → Deployment lifecycle events → failed instance-এর View events।
  2. Failed event-এর error code link ক্লিক করুন।

অনেক instance থাকলে প্রতিটিতে connect করা কষ্টকর। CloudWatch Logs ব্যবহার করা ভালো।

CloudWatch Logs-এ Log Streaming

Prerequisites

  1. EC2 instance-এর IAM role-এ CloudWatchAgentServerPolicy attach করুন।
  2. EC2-তে CloudWatch agent install করুন।

CloudWatch Agent Install

# Download
wget https://s3.amazonaws.com/amazoncloudwatch-agent/amazon_linux/amd64/latest/amazon-cloudwatch-agent.rpm

# Install
sudo rpm -U ./amazon-cloudwatch-agent.rpm

# Configuration wizard চালান
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-config-wizard

Wizard-এ log file path দিন:

/opt/codedeploy-agent/deployment-root/deployment-logs/codedeploy-agent-deployments.log

Log stream: {instance_id} (instance ID দিয়ে stream name তৈরি হবে)।

sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl -m ec2 -a status

ASG ও ALB সহ Deployment Group

Architecture

flowchart LR LB["Application Load Balancer\nDNS: my-alb.eu-west-1.elb.amazonaws.com"] TG["Target Group\nmy-alb-target-group"] ASG["EC2 Auto Scaling Group\nmy-auto-scaling-group\n(2+ instances)"] CP["CodePipeline\nDeploy Stage"] CD["CodeDeploy\nDeployment Group:\nMyAutoScalingGroup"] LB --> TG --> ASG CP --> CD --> ASG

ASG ও ALB সহ CodeDeploy architecture।

Setup Steps

  1. বিদ্যমান EC2 instance থেকে AMI তৈরি করুন।
  2. AMI থেকে Launch Template তৈরি করুন (IAM profile, security group সহ)।
  3. Application Load Balancer তৈরি করুন (Internet-facing, HTTP 80)।
  4. ALB-এর জন্য আলাদা security group তৈরি করুন।
  5. Target Group তৈরি করুন (type: Instances, HTTP 80, default VPC)।
    Target group-এর Deregistration delay 300s (5 min) থেকে কমিয়ে 60s রাখুন। না হলে CodeDeploy deployment অনেক বেশি সময় নেবে।
  6. Auto Scaling Group তৈরি করুন: Launch template ব্যবহার করে, সব AZ, ALB target group attach করুন, desired/min/max = 2।

    Health check grace period বাড়িয়ে নিন যদি application deploy হতে সময় লাগে।

  7. CodeDeploy Application-এ নতুন deployment group: MyAutoScalingGroup।
    • Environment configuration: Amazon EC2 Auto Scaling groups।
    • Load balancer: Enable, target group নির্বাচন করুন।

In-Place All-At-Once Deployment

Default deployment configuration: CodeDeployDefault.AllAtOnce — সব instance-এ একসাথে deploy করে।

Lifecycle (ALB সহ)

sequenceDiagram participant ALB participant CodeDeploy participant Instances as All Instances CodeDeploy->>ALB: Deregister all instances (BlockTraffic) Note over ALB,Instances: Website DOWN! কেউ traffic পাচ্ছে না ALB-->>CodeDeploy: Deregistration complete CodeDeploy->>Instances: Deploy new revision Instances-->>CodeDeploy: Deployment complete CodeDeploy->>ALB: Register all instances (AllowTraffic) Note over ALB,Instances: Website UP - new version

In-Place All-At-Once: সব instance একসাথে offline → deploy → online।

সুবিধা ও অসুবিধা

  • ✅ Fast — সব instance parallel-এ deploy হয়।
  • ❌ Downtime — সব instance একসাথে offline থাকে deployment-এর সময়।
  • ❌ Failure হলে সব instance একসাথে broken version পায়।
  • ✅ Use case: emergency hotfix deployment যেখানে speed priority।

ASG Scale Out হলে কী হয়

CodeDeploy deployment group-এর সাথে ASG associate করলে একটি lifecycle hook automatically তৈরি হয়।

এই hook-এর কারণে:

  • ASG নতুন instance launch করলে সেই instance Pending:Wait state-এ থাকে।
  • CodeDeploy automatically একটি নতুন deployment trigger করে।
  • Deployment group-এর last known successful revision নতুন instance-এ deploy করা হয়।
  • Deployment সফল হলে instance InService state-এ যায় এবং target group-এ register হয়।
একটি ASG-এ একবারে শুধুমাত্র একটি CodeDeploy deployment group associate করুন। একাধিক deployment group conflict করে এবং instance repeatedly terminate ও relaunch হতে পারে।

In-Place Rolling Deployment

Configuration: CodeDeployDefault.OneAtATime বা HalfAtATime।

Deployment group edit করে deployment configuration পরিবর্তন করুন।

Rolling deployment: একটি instance-এ deploy, বাকিরা serve করতে থাকে।

সুবিধা ও অসুবিধা

  • ✅ Minimum downtime — পুরো fleet কখনো offline যায় না।
  • ❌ Deployment-এর সময় দুটো version একসাথে serve হয়।
  • ❌ Angular-এ ভিন্ন file names কারণে blank page দেখাতে পারে।
  • ❌ All-at-once-এর তুলনায় বেশি সময় লাগে।
  • ✅ Failure হলে remaining instances-এ deploy stop হয়, existing fleet serve করতে থাকে।

Automated Rollback

Deployment group edit → Advanced → Roll back when a deployment fails enable করুন।

কীভাবে কাজ করে (In-Place Rolling)

  • Deployment failure হলে CodeDeploy automatically একটি rollback deployment তৈরি করে।
  • Rollback deployment শুধুমাত্র failed instance-এ last known successful revision deploy করে।
  • Deploy success করা instances-এ rollback হয় না।
  • Revision: সবচেয়ে শেষ successful deployment-এর revision।
Pipeline-এ deploy action fail করলে CodePipeline-এর execution fail হয়, automated rollback হলেও। CodeDeploy-এর rollback CodePipeline-এর failure state পরিবর্তন করে না।

Rollback trigger করার script example (ValidateService hook-এ):

#!/bin/bash

echo "This script will fail!"
exit 1

Blue/Green Deployment

Blue/Green deployment-এ existing instances-এ deploy না করে সম্পূর্ণ নতুন instance fleet তৈরি করা হয়।

Flow

flowchart TD S1["Step 1: Green Fleet Provision\nCodeDeploy Blue ASG duplicate করে\nনতুন ASG (green) তৈরি করে"] S2["Step 2: Deploy to Green Fleet\nনতুন revision সব green instances-এ deploy"] S3["Step 3: Traffic Switch\nGreen instances ALB-তে register\nBlue instances ALB থেকে deregister"] S4["Step 4: Blue Fleet Terminate\nOriginal ASG ও instances terminate"] S1 --> S2 --> S3 --> S4

Blue/Green deployment-এর 4টি ধাপ।

Configuration

  • Deployment group-এ Blue/green deployment type নির্বাচন করুন।
  • Replacement instance provisioning: Automatically copy Amazon EC2 Auto Scaling group (default)।
  • Traffic reroute: Reroute traffic immediately (default) বা নির্দিষ্ট wait time।
  • Termination: Terminate immediately (default) বা manually later।
  • Deployment configuration: Green fleet-এ AllAtOnce — তারা traffic serve করছে না, তাই rolling দরকার নেই।

সুবিধা ও অসুবিধা

  • ✅ Production একদম unaffected — failure হলেও blue fleet serve করতে থাকে।
  • ✅ Multiple version একসাথে serve হওয়ার সমস্যা নেই (traffic switch এক ধাপে)।
  • ❌ Deployment-এর সময় instance count double হয় — cost বাড়ে।
  • ❌ AWS account-এ পর্যাপ্ত EC2 capacity থাকতে হবে।

Blue/Green Deployment Failure

Green fleet-এ deployment fail করলে:

  • Step 2 fail হয় — traffic switch (Step 3) হয় না।
  • Blue fleet অপরিবর্তিত থাকে — production unaffected।
  • CodeDeploy rollback deployment তৈরি করে না — কারণ rollback-এর দরকার নেই।
  • CodeDeploy failure-তে তৈরি green ASG automatic terminate করে না — manually delete করতে হবে।

Green ASG Identify ও Delete করা

Failed deployment ID দিয়ে ASG filter করুন (tag: CodeDeployProvisioningDeploymentId)।

গুরুত্বপূর্ণ শব্দ

CodeDeploy Agent
EC2 instance-এ install করা software যা CodeDeploy poll করে ও deployment execute করে।
appspec.yml
CodeDeploy-এর deployment specification file। EC2-তে appspec.yml, ECS/Lambda-তে appspec.yaml।
Deployment Group
কোথায় deploy হবে — tagged EC2 বা ASG।
Revision
Deploy করার content — build artifact, appspec, scripts সহ।
In-Place Deployment
Existing instance-এ deploy করা।
Blue/Green Deployment
নতুন instance fleet তৈরি করে deploy, তারপর traffic switch।
AllAtOnce
সব instance-এ একসাথে deploy। Fast কিন্তু downtime।
OneAtATime / HalfAtATime
Rolling deployment — একটি বা অর্ধেক instance at a time।
Automated Rollback
Failure-তে automatically last successful revision deploy।
Lifecycle Hook (ASG)
CodeDeploy ASG-এ attach করা hook যা scale out-এ automatic deployment trigger করে।
Deregistration Delay
ALB target group-এ in-flight requests drain করার সময় (default 300s)।
ValidateService
Deployment lifecycle-এর শেষ hookable event — validation script চালানোর জায়গা।

সারাংশ

  • CodeDeploy EC2 instance-কে directly access করে না — agent poll করে deployment নেয়।
  • EC2 instance-এ AmazonEC2RoleforAWSCodeDeploy policy সহ IAM role দিতে হবে।
  • appspec.yml source code root-এ থাকতহবে এবং build artifact-এ include করতে হবে।
  • Build artifact-এ appspec ও deploy scripts include করতে buildspec-এর artifacts section আপডেট করতে হবে।
  • In-Place All-At-Once: Fast, downtime হয়। Rolling: Minimum downtime, multiple versions serve। Blue/Green: Production unaffected, cost বাড়ে।
  • ASG-এ CodeDeploy deployment group associate করলে scale out-এ automatic deployment।
  • Blue/Green failure-এ rollback দরকার নেই — blue fleet অপরিবর্তিত থাকে। Green ASG manually delete করতে হবে।
  • Target group deregistration delay কমিয়ে 60s রাখুন deployment speed-এর জন্য।

নিজেকে যাচাই করুন

১. EC2 instance-এ CodeDeploy agent install করার আগে কোন IAM permission setup করতে হবে এবং কেন?

EC2 instance-এ AmazonEC2RoleforAWSCodeDeploy policy সহ IAM instance profile attach করতে হবে। কারণ CodeDeploy agent deployment-এর সময় revision (build artifact) CodeDeploy-এর দেওয়া S3 URL থেকে download করে। এই S3 access-এর জন্য permission দরকার।

২. appspec.yml-এর files section-এ source: / দিলে কী হয়?

Revision-এর সব files ও folders copy হবে destination-এ। শুধু নির্দিষ্ট folder copy করতে চাইলে সেই path দিতে হবে, যেমন source: dist/my-angular-project।

৩. In-Place Rolling deployment-এ Angular application-এ blank page কেন দেখা যায়?

Angular প্রতিটি build-এ JavaScript ও CSS files-এর unique hash-based name generate করে। Rolling deployment-এর সময় পুরনো version ও নতুন version simultaneously serve হয়। Load balancer যদি index.html পুরনো instance থেকে এবং JavaScript files নতুন instance থেকে serve করে, filename mismatch-এর কারণে blank page দেখায়।

৪. Blue/Green deployment failure হলে CodeDeploy automated rollback তৈরি করে কিনা এবং কেন?

না। Blue/Green deployment failure-এ automated rollback দরকার নেই কারণ Blue fleet (original instances) সম্পূর্ণ অপরিবর্তিত থাকে এবং production traffic serve করতে থাকে। কোনো instance-এ broken revision deploy হয়নি। তবে Green ASG manually delete করতে হবে।

৫. ASG scale out হলে CodeDeploy কোন revision deploy করে?

Deployment group-এর last known successful revision deploy করা হয় — অর্থাৎ সেই deployment group-এ সবচেয়ে শেষ সফল deployment-এর revision।
