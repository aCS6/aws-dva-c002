Git ও CodePipeline — পরিচিতি

S3 bucket source হিসেবে ব্যবহার করা সহজ হলেও, real-world software development-এ team collaboration এবং change tracking-এর জন্য Git repository অপরিহার্য। এই কারণে production pipeline-গুলোতে Git repository-ই primary source হিসেবে ব্যবহার হয়।

Git — সংক্ষিপ্ত পরিচিতি

Git হলো একটি open-source, distributed version control system যা 2005 সালে Linux kernel development-এর জন্য তৈরি হয়েছিল। Stack Overflow-এর 2022 survey অনুযায়ী প্রায় 94% developer Git ব্যবহার করেন।

Repository
Project-এর সব file, folder এবং তাদের change history রাখার জায়গা।
Commit
Repository-এর একটি সম্পূর্ণ snapshot। Git প্রতিটি commit-এ প্রতিটি file-এর পুরো content সংরক্ষণ করে (শুধু diff নয়)।
Local Repository
আপনার নিজের computer-এ থাকা repository-র copy। Commit সবার আগে local-এ যায়। এটি Git-কে distributed system বানায়।
Remote Repository
Internet বা network-এ থাকা shared repository (যেমন GitHub)। git push দিয়ে local change remote-এ পাঠানো হয়।
Branch
Main code line (master/main) থেকে আলাদা করে কাজ করার ব্যবস্থা। Master branch-এ merge না করা পর্যন্ত পরিবর্তন isolated থাকে।
Tag
Git history-র একটি নির্দিষ্ট সময়ের reference। সাধারণত software version (যেমন v1.0.0) চিহ্নিত করতে ব্যবহার হয়। Branch-এর মতো নতুন commit যোগ হয় না।

CodePipeline-এ Git কীভাবে কাজ করে

Remote Git repository-কে pipeline-এর source location হিসেবে configure করলে:

  1. Developer local-এ change করে commit তৈরি করে remote repository-তে push করে।
  2. Push event AWS CodePipeline-কে trigger করে।
  3. CodePipeline repository থেকে latest code pull করে।
  4. Code pipeline stages-এর মধ্য দিয়ে যায় — build, test, deploy।
flowchart LR DEV["Developer\ngit commit + push"] -->|push event| GH["GitHub\n(remote repo)"] GH -->|webhook/event| CP["AWS CodePipeline\nSource Stage"] CP -->|SourceArtifact zip| AS["S3 Artifact Store"] AS --> BUILD["Build Stage\n(optional)"] BUILD --> DEPLOY["Deploy Stage"]

Git push থেকে CodePipeline trigger হয়ে deployment পর্যন্ত flow।

Pipeline-এ Branch Strategy

CodePipeline-এ একটি specific branch track করা যায়। সাধারণ pattern:

  • master বা main branch → production pipeline।
  • আলাদা production branch → production deployment পাইপলাইন।
  • Development branch → staging pipeline।

এভাবে development এবং production deployment আলাদা রাখা যায়।

AWS CodeCommit Deprecation ও GitHub-এ Migration

AWS CodeCommit ছিল AWS-এর নিজস্ব source control service। কিন্তু July 2024-এর শেষে AWS CodeCommit deprecated করেছে।

গুরুত্বপূর্ণ: নতুন AWS account-এ আর CodeCommit repository তৈরি করা যাবে না। পুরনো account-এ existing repository থাকতে পারে, তবে নতুন development-এ CodeCommit ব্যবহার না করাই ভালো।

AWS-এর recommendation হলো GitHub, GitLab বা Bitbucket-এ migrate করা। এই কোর্সে GitHub-কে primary replacement হিসেবে ব্যবহার করা হয়েছে।

CodeConnections (formerly CodeStar Connections): AWS Developer Tools-এ third-party Git provider connect করার service-এর নাম "CodeStar Connections" থেকে "CodeConnections"-এ rename করা হচ্ছে। Console-এ যদি "CodeStar" দেখেন, সেটি একই service।

Supported Git Providers

AWS CodePipeline বর্তমানে নিচের Git provider support করে:

Provider Version Notes
GitHub Version 2 (recommended) AWS Connector for GitHub app ব্যবহার করে।
GitHub Version 1 (legacy) OAuth token-based, deprecated — ব্যবহার করবেন না।
GitHub Enterprise Server — Self-hosted GitHub এর জন্য।
Atlassian Bitbucket Cloud — Bitbucket Cloud repository support।
GitLab — GitLab.com এবং GitLab self-managed উভয়ই।
AWS CodeCommit — Deprecated — নতুন account-এ ব্যবহার করা যাবে না।

⚠️ AWS সময়ের সাথে নতুন provider যোগ করতে পারে। Latest list-এর জন্য AWS documentation দেখুন।

GitHub Connection Setup — AWS Developer Tools

Third-party Git provider (যেমন GitHub) থেকে pipeline তৈরি করার আগে AWS account-এ একটি connection configure করতে হবে। এই connection AWS Developer Tools-এর Connections section থেকে manage করা হয়।

Connection কীভাবে কাজ করে

Connection তৈরি করলে AWS Connector for GitHub নামে একটি GitHub App install হয়। এই app AWS-কে GitHub repository থেকে code পড়ার permission দেয়।

sequenceDiagram participant U as Developer participant AWS as AWS Developer Tools participant GH as GitHub U->>AWS: Create Connection (GitHub provider) AWS->>GH: Redirect to GitHub OAuth GH->>U: Request authorization U->>GH: Authorize AWS Connector GH->>AWS: Return to AWS AWS->>U: Install AWS Connector for GitHub App U->>GH: Choose account/org + repo scope GH-->>AWS: App installed U->>AWS: Click "Connect" to finish Note over AWS: Connection status = "Available"

GitHub connection তৈরির ধাপ — AWS এবং GitHub-এর মধ্যে authorization flow।

Connection তৈরির ধাপ

  1. AWS Management Console-এ CodePipeline Console খুলুন।
  2. বাম menu-তে Settings → Connections ক্লিক করুন।
  3. Create connection ক্লিক করুন।
  4. Provider হিসেবে GitHub নির্বাচন করুন।
  5. Connection name দিন, যেমন: GitHub connection
  6. Connect to GitHub ক্লিক করুন — GitHub-এ redirect হবে।
  7. GitHub-এ Authorize AWS Connector for GitHub ক্লিক করুন।
  8. AWS Developer Tools-এ ফিরে এলে Install a new app ক্লিক করুন।
  9. GitHub-এ যে account বা organization-এ repository আছে সেটি নির্বাচন করুন।
  10. Repository access:
    • All repositories — সহজ, ভবিষ্যতে নতুন repo স্বয়ংক্রিয়ভাবে covered।
    • Only select repositories — নিরাপদ, কিন্তু নতুন repo যোগ করতে reconnect করতে হবে।
  11. Install ক্লিক করুন।
  12. AWS-এ ফিরে Connect ক্লিক করুন।
  13. Connection-এর status Available হলে সফল।
একটি connection একাধিক pipeline-এ ব্যবহার করা যায়। একই GitHub account-এর জন্য একটি connection-ই যথেষ্ট।

GitHub Repository তৈরি ও Code Push

GitHub-এ Repository তৈরি

  1. GitHub-এ login করুন।
  2. নতুন repository তৈরি করুন। Name: my-website-repo (kebab-case convention)।
  3. Visibility: Private রাখুন।
  4. Create repository ক্লিক করুন।

Local Repository Initialize করা ও Push করা

আপনার project folder-এ terminal খুলুন এবং নিচের command-গুলো চালান:

# ১. Local Git repository initialize করুন
git init

# ২. সব file stage করুন
git add .

# ৩. Initial commit তৈরি করুন
git commit -m "Version 1.0"

# ৪. GitHub repository-কে remote হিসেবে যোগ করুন
# (GitHub repository page থেকে HTTPS URL কপি করুন)
git remote add origin https://github.com/YOUR-USERNAME/my-website-repo.git

# ৫. master branch-এ push করুন
git push origin master
S3 source-এর সাথে পার্থক্য: GitHub source-এ zip package তৈরির দরকার নেই। File-গুলো সরাসরি repository-তে রাখুন। CodePipeline নিজেই source code zip করে artifact store-এ রাখে।
Git commit message গুরুত্বপূর্ণ: Source revision-এ commit message দেখা যায়। Pipeline history-তে কোন version কখন deploy হয়েছে বুঝতে সাহায্য করে। অর্থপূর্ণ message ব্যবহার করুন।

Source Stage — GitHub (Version 2) Configuration

  • Source provider: GitHub (Version 2) নির্বাচন করুন।

    ⚠️ "GitHub (Version 1)" OAuth-based এবং deprecated। "GitHub (Version 2)" ব্যবহার করুন যা AWS Connector for GitHub app ব্যবহার করে।

  • Connection: আগে তৈরি করা GitHub connection নির্বাচন করুন। Status "Ready" দেখালে connection সঠিকভাবে কাজ করছে।
  • Repository name: আপনার GitHub repository নির্বাচন করুন।
    যদি repository দেখা না যায়, GitHub-এ "AWS Connector for GitHub" app-এর repository access settings-এ সেই repository যোগ করুন।
  • Default branch: master
  • Output artifact format: CodePipeline default (zip)। অন্য option হলো "Full clone" — এটি শুধুমাত্র CodeBuild action-এ কাজ করে।

Trigger Filter Configuration

Trigger filter দিয়ে কোন Git event-এ pipeline trigger হবে তা নিয়ন্ত্রণ করা যায়:

Option আচরণ
No filter (default) configured branch-এ যেকোনো push-এ trigger হয়।
No triggers Automatic trigger বন্ধ। শুধুমাত্র manually trigger করা যাবে।
Push → Branch filter নির্দিষ্ট branch include/exclude করে trigger করুন।
Push → Tag filter নির্দিষ্ট Git tag push হলে trigger হয়।
Push → File path filter নির্দিষ্ট file path-এ পরিবর্তন হলে trigger হয়।
Pull Request events PR open/update হলে trigger হয়।

এই উদাহরণে filter দেওয়া হয়নি — master branch-এ যেকোনো push pipeline trigger করবে।

  1. Next → Build stage: Skip build stage → Skip।
  2. Deploy stage: Amazon S3 provider, production bucket, ✅ Extract file before deploy।
  3. Next → Create pipeline।
Pipeline তৈরি হওয়ার সাথে সাথে GitHub-এর latest commit থেকে automatic execution শুরু হবে।

GitHub Source Action-এর বিশেষত্ব

GitHub source-এ S3 source-এর তুলনায় কিছু পার্থক্য আছে:

  • Source revision-এ S3 version ID-এর বদলে Git commit ID এবং commit message দেখা যায়।
  • Action details-এ commit link দেওয়া থাকে — click করলে GitHub-এর সেই commit-এ redirect হয়।
  • Input tab-এ GitHub connection ARN, repository ID, branch এবং trigger detection settings দেখা যায়।
  • DetectChanges: true মানে automatic trigger enabled।

Git Push দিয়ে Pipeline Trigger করা

Change করে Push করার ধাপ

  1. Local-এ index.html বা অন্য file পরিবর্তন করুন।
  2. পরিবর্তন save করুন।
  3. Terminal-এ নিচের command চালান:
# ইতিমধ্যে tracked file-এ change করলে -a flag দিয়ে auto-stage করা যায়
git commit -a -m "Version 2.0"

# Remote repository-তে push করুন
git push origin master
git commit -a শুধুমাত্র ইতিমধ্যে tracked file-এর জন্য কাজ করে। নতুন file যোগ হলে আগে git add filename দিয়ে stage করতে হবে।
  1. git push সম্পন্ন হওয়ার পরপরই CodePipeline Console-এ Source stage-এর execution time প্রায় "Just now" হয়ে যাবে।
  2. Source revision-এ commit message দেখা যাবে।

Execution History-তে Git Trigger

Execution history-তে Git push দিয়ে trigger করা execution-এ:

  • Trigger: "Git push" + commit ID দেখা যায়।
  • Source revision: Commit ID + commit message।
  • Repository link ক্লিক করলে GitHub repository-তে যাওয়া যায়।
  • Timeline-এ source action-এর link ক্লিক করলে সেই specific commit-এ যাওয়া যায়।

Pipeline creation-এর execution-এ trigger দেখায় CreatePipeline, এবং manually trigger করলে StartPipelineExecution দেখায়। Git push-এ commit ID সহ "Git push" দেখায়।

পরবর্তী সেকশনে কী আসছে

এই সেকশনের পরের সব উদাহরণে GitHub repository থেকেই pipeline trigger হবে। Source provider পরিবর্তন হলেও build এবং deploy stage-এর concept একই থাকে। পরবর্তী section থেকে AWS CodeBuild দিয়ে build stage যোগ করা হবে।

সারাংশ

  • AWS CodeCommit July 2024-এ deprecated হয়েছে। নতুন account-এ GitHub, GitLab বা Bitbucket ব্যবহার করতে হবে।
  • GitHub repository pipeline-এ source হিসেবে ব্যবহার করতে প্রথমে AWS Developer Tools-এ connection তৈরি করতে হবে।
  • Connection-এ "AWS Connector for GitHub" GitHub App install করতে হয়।
  • Pipeline-এ সবসময় GitHub (Version 2) provider ব্যবহার করুন — V1 deprecated।
  • Default trigger (no filter) দিলে configured branch-এ যেকোনো push pipeline trigger করে।
  • Source revision-এ Git commit ID ও commit message থাকে — meaningful commit message লেখুন।
  • git commit -a -m "message" && git push origin master — এটুকুই pipeline trigger করতে যথেষ্ট।

নিজেকে যাচাই করুন

১. GitHub (Version 1) এবং GitHub (Version 2) source provider-এর মধ্যে মূল পার্থক্য কী?

Version 1: OAuth-based token ব্যবহার করে — deprecated, security concern আছে।

Version 2: AWS Connector for GitHub app ব্যবহার করে — recommended, আরো secure, fine-grained repository permission।

২. GitHub source action-এ "Output artifact format" এর দুটি option কী এবং কখন কোনটি ব্যবহার করবেন?

CodePipeline default (zip): Source code zip করে artifact store-এ রাখে। সব action type-এ কাজ করে।

Full clone: Git repository সম্পূর্ণ clone করে Git metadata (commit history, branches) সহ রাখে। শুধুমাত্র CodeBuild action-এ supported — যেমন commit ID বা Git history access দরকার হলে।

৩. AWS Connector for GitHub app-এ "All repositories" vs "Only select repositories" — কোনটি বেছে নেওয়া উচিত?

All repositories: সহজ setup, ভবিষ্যতে নতুন repository স্বয়ংক্রিয়ভাবে covered। কিন্তু AWS-কে সব repo-তে access দেওয়া হয়।

Only select repositories: Least-privilege principle অনুসরণ করে, কিন্তু নতুন repo যোগ করলে connection reconfigure করতে হবে।

Security-conscious environment-এ নির্দিষ্ট repository নির্বাচন ভালো; learning/development-এ all repositories সহজ।

৪. git commit -a flag কখন কাজ করে না?

git commit -a শুধুমাত্র ইতিমধ্যে Git দ্বারা tracked file-এ কাজ করে। নতুন file যোগ করলে আগে git add filename বা git add . দিয়ে stage করতে হবে।

৫. Trigger filter-এ "No filter" এবং "No triggers" এর পার্থক্য কী?

No filter: Automatic trigger enabled — configured branch-এ যেকোনো push pipeline trigger করে।

No triggers: Automatic trigger disabled — pipeline শুধুমাত্র manually (Release change) trigger করতে হবে।
